# Merry Christmas · 手势粒子圣诞树

MediaPipe Hands + Three.js 的手势交互圣诞粒子树，带 MP3 音乐驱动的呼吸动画。

三条主线：**粒子树负责逼真度，手势负责形态与互动，音乐负责亮度与能量。**

## 快速开始

必须通过 http 访问（摄像头权限与 ES Module 都需要），双击 `start.bat` 即可，
它会启动本地服务并打开浏览器。

手动启动：

```bash
python serve.py --port 8123
# 然后打开 http://127.0.0.1:8123/index.html
```

`serve.py` 是带 **gzip + 长缓存** 的静态服务器，不要换回 `python -m http.server`：
手势模型和 wasm 加起来 17MB，压缩后只要 9MB，手机首次打开差距很明显。

首次打开会请求摄像头权限，允许后把手举到镜头前即可。

## 加载策略

首屏排队的其实是三件事：把树画出来（本地算力）、把模型下载下来（网络）、
再把摄像头和推理器真正点亮（授权 + wasm + `createFromOptions`）。实测冷启动的耗时
分布在这三处，于是逐条拆开优化：

1. **压缩版 three**：`three.module.min.js` 655KB（gzip 163KB），比未压缩版省 88KB
2. **modulepreload 摊平依赖图**：ES module 是「下载 → 解析 → 才知道 import 谁」的瀑布，
   每层多一个 RTT。把整张图写在 `<head>` 里并发下载，慢网上省掉两三个来回
3. **模型请求提前到 head**：`src/modelPreload.js` 只依赖 3KB 的 assetLoader，
   比 main.js（要等 163KB 的 three）早几百毫秒执行；再配一条
   `<link rel=preload as=fetch>` 让请求在 HTML 解析时就发出（实测 +13ms，原来 +1.3s）
4. **等真实绘制再建场**：`nextPaint()` 是 rAF + 一个宏任务，而不是
   `rAF(() => resolve())` —— 后者的 await 后续仍在同一帧、绘制之前，紧接着的长任务
   会把这一帧吞掉，FCP 在 220ms 和 1.3s 之间随机跳
5. **重活挪到空闲时段**：比心字幕 / 孔明灯 / 点赞 / OK 四段特效（合计十几万颗粒子）
   改为动态 import + `requestIdleCallback` 延后构建，首帧只需要树
6. **gzip**：wasm 9.4MB → 2.9MB，模型 7.8MB → 5.9MB（`serve.py` 自动做，CDN 本身也有）
7. **两级缓存**：`/vendor` `/assets` 发一年 immutable，配合 IndexedDB，
   第二次打开**零网络请求**（实测模型从 1452ms/5.7MB 变成 353ms/0 字节）
8. **音乐让路，但不让人干等**：默认曲是流式的，点之前一个字节都不取，不和模型抢带宽；
   点了只等开头几十 KB 就出声，边播边拉。
   首屏另弹一张确认卡「先听一首歌？」——用户点了才发请求，元数据一到就出声，等模型的几秒就有了声音

首屏进度条把三件事合在一起：**场景 35%、模型 30%、手势链路 35%**
（`BOOT_W`，按实测耗时分的，不是拍脑袋的 1/3）。

**三者全部到位才收遮罩。** 早先只等模型就放人进去，结果场景里摄像头小窗还在转圈、
举手没反应——看着像坏了。现在遮罩收起的那一刻 `gesture.ready` 一定已经是 `true`。

界面是四件套：

| 元素 | 作用 | 位置 |
| --- | --- | --- |
| 状态文案 | 说「现在在干什么」，**中英双行**（`正在唤醒雪夜…` / `Waking up the snow night…`），一路走到 `正在下载手势模型 3.9 / 7.5 MB`、`正在等待摄像头…` | `paintLoading()` |
| 百分比数字 | 说「到几成」，`tabular-nums` 不抖宽度；逐帧追目标值（`stepPct` 系数 0.17，差 25 分以上时给 0.42 加速），大跳变不会滞后 | `#loadingPctNum` |
| 进度条 | 宽度交给 CSS 过渡；填充段有 2.4s 一次的扫光，等待中轨道上再跑一道 `is-wait` 流光 | `styles.css` |
| 音乐确认卡 | 首帧之后从底部浮上来问一句「先听一首歌？ / Enjoy some music?」 | `#musicPrompt` |

### 「手势链路」这一段为什么按时间估算

`createFromOptions` 不给任何细粒度进度回调，只有「好了没」。硬写几个台阶
（`0.68 → 0.84 → 1`）会让进度条僵在九十几好几秒，比慢慢爬更让人怀疑死机。
所以这一段的显示值完全由时间决定：**从 `rigT0` 起 4 秒线性爬满**，真就绪时
`stepRig(1)` 直接补满。用线性而不是指数渐近——指数在尾巴上几乎不动，正好是
用户最焦虑的那几秒。台阶值只用来判断「完成没」，绝不参与插值。

### 三条兜底

| 情况 | 行为 |
| --- | --- |
| 树已经能看、后面还在等 | 4 秒后浮出「不等了，先看看树」，不让人为后台组件干等 |
| 等太久（22 秒） | 自动放行，遮罩写「准备好了 · 手势马上可用」 |
| 摄像头被拒 | 立即放行（不等超时），遮罩写「摄像头未授权 · 进入音乐模式」，右上角同步提示 |

遮罩收起前会把数字补到 100，并且把还挂着的音乐确认卡一起收掉。


换源：

| 地址 | 行为 |
| --- | --- |
| 默认 | localhost 用本地 `vendor/`，其它域名先试 CDN |
| `?src=local` | 强制本地，断网可用 |
| `?src=cdn` | 强制 jsdelivr / Google 存储，适合只部署页面不部署 vendor |
| `?src=auto` | 先 CDN，失败回落本地 |

任意来源失败都会自动换另一个，不会卡死。

## 手势

| 手势 | 效果 |
| --- | --- |
| 双手拉弓 | 两手一前一后拉开 → 右下角出现粒子弓、左上角亮起粒子心；拉得越开弦越弯，**两手一松＝放箭**，箭穿红心、心炸成粒子被风吹散（屏幕上会显示拉弓进度和下一步提示） |
| 双手开合 | 缩放整棵树，彩灯随之依次点亮（**当前默认屏蔽**，大间距会干扰拉弓/比心；缩放可改用屏幕拖拽） |
| 拍手 | 爆雪 + 冲击波 + 星光脉冲（**当前默认屏蔽**，打节拍容易误触；按 **S** 键仍可手动触发调试） |
| 侧掌扇风 | 掌心朝左/右、手掌竖着左右扇 → 整棵树绕自身中轴左右旋转（漩涡感），松手后惯性慢慢停 |
| 双手比心 | 两手各自把拇指尖和食指尖合上、并排举在身前 → 心形光尘浮起，雪花转粉、彩灯转暖 |
| 打电话（比 6） | 拇指 + 小指伸出、中间三指收拢 → 六盏孔明灯从树旁陆续升起，升到树顶化进夜色，灯口一路撒火星 |
| 点赞（竖大拇指） | 拇指竖起朝上、其余四指全部收回 → 整棵树撒下一层金箔纸屑，翻转着落、落地前淡出 |
| 单手 OK | 拇指食指捏成圈、中指无名指小指伸开 → 满屏爱心 + 银色流星雨 + 从底部升空的烟花，散尽后浮出「miss you」，字再被风吹走（约 8.5 秒） |
| 握拳 | 树体向中轴收拢、彩灯转暗（**当前默认关闭**，半握拳误判多） |
| 掌心向上托举 | 生成承接区域，接住天上掉落的礼物并计数（**当前默认关闭**） |

没人操作时树会**自己慢慢转**，约 31 秒一圈（`SPIN.idleRate = 0.20` rad/s），
不然正面一动不动像张静态图。用手扇风时自转叠加在上面，0.2 相比手动的 2~5 rad/s
几乎看不出来，松手后自然回到慢转。

### 「双手拉弓」怎么判定（取代了原来的「抓取张开」）

> **两只手一前一后拉开（至少一只手别摊平）→ 右下角出现粒子弓、左上角亮起粒子心。
> 拉得越开，弓弦弯得越厉害、箭也退得越多；两手一松＝放箭，
> 箭沿对角线射进红心，心炸成粒子随风飘散。**

张手炸裂那段代码还在（`BURST_CFG`），只是 `GESTURE_SWITCH.burst` 改成了 `false`，
想要回来把它打开、`bow` 关掉即可。

**判定分两层**：`GestureController._computeBow()`

| 层 | 判据 | 参数（`BOW_CFG`） |
| --- | --- | --- |
| 能不能拉 | 两只手 + 高度差 / 手宽小 + 至少一只手不是完全摊开 | `levelZero: 2.30`、`gripMin: 0.30`、`hold: 150ms` |
| 拉了多少 | `smoothstep((间距/手宽 - start) / (full - start))` | `start: 1.12`、`full: 3.60` |

归一化除的是**手宽**而不是像素：手离镜头远近、用户手大手小都不影响拉弓量。

**这几个数是从「标准姿势」往回松了两轮的结果**。第一版按教科书量：
两手水平、间距 4.6 手宽、勾弦的手必须半握（`clutch > 0.52`）、放开要快过 3.2 手宽/秒。
实测绝大多数人四条里至少踩一条，于是「比划半天弓不出来」：

| 原来的坑 | 为什么不行 | 现在 |
| --- | --- | --- |
| 两手必须水平（`levelZero 1.65`） | 画面里的弓是斜指左上的，人一比划自然带斜度 | 2.30 |
| 拉满要 4.6 手宽 | 两只手都在胸前，胳膊展开也就 3 手宽 | 3.60 |
| 勾弦的手必须握拳（`clutch > 0.52`） | 自然放松的手 `clutch ≈ 0.4`，永远够不着 | 0.30（只排除摊平的掌） |
| 入场要稳 220ms | 抬手路过就掉，感觉「不跟手」 | 150ms |

**为什么不和别的手势打架**（靠几何构型互斥，不靠时序）：

| 手势 | 区别 |
| --- | --- |
| 双手比心 | 比心要两手**并拢**（指尖距离 < 1.3 手宽），可掌间距照样超过 1.12 手宽、捏半心时 `pinch` 又高 —— 光靠几何分不开，所以 `_computeBow` 里直接读上一帧的 `heart` 状态把它否掉 |
| 双手开合缩放 | 两手都摊平（`clutch ≈ 0`）；拉弓要求 `clutch > 0.30` |
| 拍手 | 发生在拉弓**之后** —— 所以拉弓期间反过来把 clap 压掉 |

最后一条是必须的：放箭那一下两手是快速合拢的，几何上和拍手一模一样，
不压制的话每放一箭都会顺带炸一场暴雪，把箭的轨迹盖掉。

**放箭只有一条判据：pull 从峰值回落 > 0.15。**
峰值以 1.15/s 缓慢回落，所以「慢慢把手放下」（≈0.5/s）永远追不上它 ——
不需要用户真的做出多快的手速，也不需要「两手快速合拢」那种刻意的动作。

> 曾经还有一条「两手合拢速度 < -3.2 手宽/秒」，是**错的**：手一旦被跟丢重捕，
> 坐标会跳，一帧就能造出几百手宽/秒的假速度，于是凭空放出一箭。
> 现在这个速度只用于探针显示（并且钳在 ±20）。

拉满之后一只手直接出了画面（检测丢失，且峰值 > 0.34）也算放箭，否则用户会以为没反应。

还要压住缩放：拉弓的姿态本身就是「两手分开」，router 会把它判成放大，
于是整棵树在描弓的过程中被推大。`InteractionRouter.bowW` 在弓出现时把缩放权重让出去。

**「怎么发射出去」得让界面自己说**：弓出现时底部中间会浮出一条进度条
（`#bowTip`，`main.js` 里每帧按 `archery.pull` 更新），文案分五档 ——
`两手指尖分开 · 一只手半握` → `两手再拉开一点` → `继续拉 · 松手立即放箭` →
`已拉满 · 两手一松就放箭` → 放完显示 `箭已出弦 · 再拉一次`。
平时它是隐藏的：常驻等于一直提醒用户「你还没拉弓」。

**视觉部分**（`src/BowArrow.js`）—— **全部是粒子，没有一条实心几何**：

- 整组挂在 **camera 下面**、放在 z = -3.1：用户说的「右下角 / 左上角」是**屏幕位置**，
  不是世界位置。挂到相机上就成了一张固定在取景框里的图层，树怎么转、镜头怎么视差推拉都不动。
  代价是它永远在最前面 —— 所以全部 `depthTest: false` + 高 `renderOrder`。
- 弓身 = 290 颗芯 + 210 颗内光 + 44 颗外晕。**三层是必须的**：只铺一层小点时，
  点径 4px、间距 5px，眼睛看到的是「一串珠子」而不是光。这是加色混合的伪 bloom。
- 外晕要贴紧（`aOff ±0.8`）且色相偏琥珀（`g = 0.70r`）：散得太开是一团篝火烟，
  绿分量给少了低亮度的橙会读成「褐色脏雾」。
- 弓臂曲线在顶点着色器里算（`bowPoint(s)`），弦是同一个函数取 s=±1 的两个点连到弦扣，
  所以拉弓时弓梢后仰、弦弯成 V，都不需要 CPU 改顶点。
- 箭 = 84 颗芯 + 26 颗柔光 + 26 颗箭头 + 40 颗尾迹。点径必须**大于点间距**
  （154px 里 84 点 ≈ 1.8px，直径 2.4→4px），否则整支箭是虚线；颜色从尾到头渐亮，
  等亮度会被读成「一根白棍」。尾迹只在飞行时亮（`uTail`），搭在弦上拖着一条长尾巴是穿帮。
- 心 = 300 颗轮廓（**按弧长**采样参数 t，均匀取 t 会在两个尖端堆一坨）
  + 150 颗内部散点（**包围盒拒绝采样 + 射线法判内外**；用「轮廓点 × 半径」会让
  x≈0 的点全叠在竖轴上，看起来像一根穿心的骨刺）+ 70 颗大而暗的内部柔光。
- 命中时**心的同一批粒子**沿各自径向炸开被风带走（顶点着色器里的 `uScatter`），
  不需要另建一套爆炸粒子；另外还有 380 颗红金火花做二次冲击。

调试：按 **B** 看一遍完整的拉弓 → 放箭；`?debug` 的探针最后一行是
`弓 0.83 ON  距 3.2  平 0.4  握 0.7  速 -1.2`（pull / 是否成立 / 手间距 / 高度差 / 握姿 / 间距变化率）。

### 侧掌扇风怎么判定（原来的画圈 / 推拉已替换）

「画圈」在摄像头里很难稳定复现（手一转就丢关键点，圈径小的时候尤甚），
所以换成物理上更明确的三个量（`GestureController._describeHand()` + `InteractionRouter`）：

| 信号 | 含义 | 作用 |
| --- | --- | --- |
| `sideW` | 掌面侧立程度：法线 x 分量大、y 分量小 → 掌心朝侧 | 门控。掌心朝镜头（普通挥手）时直接不算 |
| `vx` | 手掌水平速度（屏宽/秒，先低通再减死区） | 换算成角速度 |
| `palmSide` | 掌心的左右朝向（±1） | 与 `vx` 同向＝主程，反向＝回程只给 55% |

转速 = `vx × sideW × towardFace × rate`，上限 5.2 rad/s（约 300°/s）。
**角度是累积的**，不是位移：停下来就停在当前角度，靠摩擦慢慢停，不会弹回正面。

`sideW` 的曲线刻意放得很宽（`|nx|` 0.28 起步、0.60 满分）。MediaPipe 的 3D 法线在
手掌侧对镜头时估得偏保守，真人「斜着侧立」常常只给到 0.5~0.6 的 `|nx|`，
用 0.40 起步的旧曲线会被判成「不是扇风」，于是手势怎么比都不转。

**防抖五道**（参数集中在 `InteractionRouter.js` 顶部 `SPIN`）：

1. 速度先做 EMA 低通（`smooth: 0.28`），摄像头的逐帧跳动不会被当成「手在动」；
2. **软死区**（`dead: 0.08`）：只取超出死区的速度，静止时的残余噪声被整段减掉，
   树不会自己缓慢自转；
3. **单帧跳变丢弃**（`jump: 4.0`）：手被重新识别、左右手标签互换、手从画面一侧跳到另一侧时，
   单帧位移会大到不可能是真挥动 —— 这种尖峰直接丢，否则树会突然反向狂转；
4. 角速度用一阶跟随（`accel: 9.5`）而不是直接赋值，手抖一下不会让转速突跳；
   已经转起来时门槛打折（`gateHold: 0.40`），追踪偶发一两帧判错也不会立刻刹停；
5. 松手后摩擦衰减（`friction: 0.85`），低于 `stopEps` 归零，避免手一松就无休止地转；
   叠在上面的 `idleRate` 空闲自转是另一回事，它一直存在。

如果真机上出现**手往右扇、树往左转**，把 `GestureController.js` 顶部的 `SIDE_SIGN` 改成 `1`。


### 手势开关（临时关掉某个手势）

`src/gestureConfig.js` 里一个常量管全部，改 `false` 即停用，不用删代码：

```js
export const GESTURE_SWITCH = {
  fist: false,   // 握拳收拢
  burst: false,  // 张手炸裂（位置已被拉弓占用）
  bow: true,     // 双手拉弓 → 箭穿红心
  spread: false, // 双手开合缩放 —— 暂时屏蔽；缩放改用「按住屏幕拖拽」也不冲突
  clap: false,   // 拍手爆雪 —— 暂时屏蔽；特效没删，按 S 键还能手动触发
  ok: true,      // 单手 OK → 爱心 + 流星雨 + 烟花 + miss you
  call: true,    // 打电话（拇指+小指）→ 放孔明灯
  like: true,    // 点赞 → 金箔纸屑
  tray: false,   // 掌心向上接礼物
  heart: true,
};
```

`fist: false` 时，`_describeHand()` 不再产出 `'fist'` 标签，**收拢（collapse）停用**，
HUD 上那条「握拳」提示也会自动隐藏。关掉它的原因：真人比心时手指常是半握状态，
MediaPipe 很容易判成 fist，树被压塌，画面里就看不见心形了。

`burst` 独立于 `fist`：炸裂不再等「握拳」，只看「五指收拢（抓取）→ 张开」这个动作序列。
`tray: false` 时 `_computeTray()` 直接返回 `null` 并清掉 `trayActive`，
礼物照常从天上落下、落地炸一小簇金光，只是没有承接区。

`spread: false` 时 `update()` 里 `state.spread` 恒为 `null` —— router 的缩放弹簧整段哑火，
树不再跟着两手间距缩放；「双手开合」提示条与底部轮换提示也一并消失。

### 为什么比心用「双手」而不是「单手」

单手比心（拇指食指交叉）在 640×480 的视频里两个指尖经常重合成一个点，关键点分辨率
只剩几个像素；而且它和「捏合」是完全相同的几何构型，误触率很高。

双手比心是多条软约束一起打分（`GestureController._computeHeart()`）：

| 信号 | 含义 | 权重区间 |
| --- | --- | --- |
| `ring` | 单手拇指尖-食指尖的闭合度 | ≤0.30 手宽满分，1.15 手宽归零 |
| `gap` | 两手「指尖中点」间距（按手宽归一） | 0.16–1.30 满分，超过 1.90 归零 |
| `level` | 两手高度差 | ≤0.85 满分，1.60 归零 |
| `rate` | 指尖间距变化速度（手宽/秒，两级平滑） | ≤2.5 不扣分，5.0 归零 |
| 保持 | 连续满足 260ms 才点亮，松手 220ms 才熄灭 | 滞回 |

### 和「双手开合缩放」怎么区分

这两个动作都是两手捏着靠在一起，几何上几乎同构，所以靠三件事分开：

1. **间距**：比心是两手并拢（一拳以内），缩放在做大开大合时 `gap` 会远超 1.3；
2. **保持**：比心是定住不动，拉拽缩放时 `gap` 一直在变，`rate` 项会扣分；
3. **优先级**：`love` 一升起来，`InteractionRouter` 就把缩放权重让出去，树定在原地，
   不会出现「心形亮起来的同时树被抽小」这种互相打架的观感。

### 比心不出效果怎么查

打开 `?debug`（例如 `http://127.0.0.1:8123/index.html?debug`），摄像头小窗下方会多出一个
绿色探针，实时显示：

```

距 0.72  平 0.14  速 0.21

```

最后一段 `· xxx` 就是卡在哪一步：

| stage | 含义 | 怎么办 |
| --- | --- | --- |
| `hands` | 没识别到两只手 | 手离镜头近一点，别出画 |
| `ring` | 拇指-食指没合上 | 两根指尖真的碰到一起 |
| `near` | 两手贴太紧（像拍手） | 稍微分开一个拳头的距离 |
| `far` | 两手离太远（当成缩放了） | 并拢一些 |
| `level` | 两手不等高 | 摆平 |
| `move` | 手还在动 | 定住别动 |
| `hold` | 条件都满足了，正在计时 260ms | 再稳 0.2 秒 |
| `clap` | 刚触发过拍手，抑制 300ms | 等一下 |
| `on` | 已点亮 | — |

阈值集中在 `GestureController.js` 顶部的 `HEART_CFG`。

### 比心结束：心散成一行字

松手瞬间，组成心形的粒子不会直接淡掉，而是飞向空中拼成 **`I love you`**，
停留约 3 秒，再被一阵从左往右的风吹散（`src/LoveMessage.js`）。

- **起点就是心形本身**：`HeartEffect` 在心形强度掉到 0.45 时把世界位置和缩放交给
  `LoveMessage`，2200 颗粒子从心形上原地起飞 —— 所以看起来是「心散开了」，而不是
  「另一个特效淡入」，这是整段动画最关键的连续性。
- **字形不是贴图**：离屏 canvas 用斜体衬线画 `I love you`（1024×300），按不透明像素
  采样成目标点集；每颗粒子带 0–380ms 随机延迟，飞行途中走一条上抛弧线（`sin(π·e)`）。
- **停留呼吸**：整行字亮度按 `0.92 + 0.08·sin(1.5t)` 起伏。
- **风散**：`wave = smoothstep(0, 1, d·1.45 - (x+3.7)·0.058)`，越靠右的粒子越晚被吹走，
  于是从左到右扫过去一道波浪，而不是整体一起消失。
- **给字幕让位**：文字在场时 `params.brightness *= 1 - 0.13·dim`、`bloom` 同步收，
  收尾随 `dissolve` 平滑恢复，不会有亮度突跳。
- 正在播字时再次比心会立刻把文字吹散（`loveMsg.cancel()`）。

时间线在 `LoveMessage.js` 顶部：`FLY 1.15s / HOLD 3.2s / BLOW 1.9s`。

### 打电话 → 放灯

拇指和小指伸出、中间三指收拢（也就是「比 6」），稳住 240ms 就把六盏灯放上天
（`src/WishLantern.js`）：灯从树的四周陆续升起，升到树顶之上化进夜色，灯口一路往下撒着火星。

判定用 `phone` 分数（`_describeHand`）：拇指离食指根的距离、小指伸直度、中间三指收拢各占一部分，
加权后 > 0.72 才算。实测张开手 0.31 / 握拳 0.36 / 比心 0.47 / 打电话 0.98，分得很开。

**为什么把原来的「666 / Miss me? / Call me」换掉**（旧实现留在 `CallDanmaku.js`，没删）：

- **画面语言重复**：OK 手势收尾已经是「miss you」金色花体，再来一次粒子文字，同一个技巧用两遍就不值钱
- **666 是弹幕梗**，放进雪夜圣诞树里气质不对
- **颜色缺一块**：树上全是冷色（墨绿 / 雪 / 月光），一整片暖橙的灯飘在夜空里，画面立刻立住
- 语义上也接得住「打电话 = 想找远方那个人」，一盏灯比一句 `call me` 含蓄

**几处取舍**：

- **灯壳只画轮廓、不铺满**：加法混合下把柱面铺满，正面几百颗叠起来就是一块白斑，连灯形都看不出。
  这里按「柱面法线朝向相机」逐点判亮度 —— 正对镜头压到 0.30（透一点纸的光），
  视线切过灯身的两条边缘提到 1.0，于是每盏灯都是「一圈亮边 + 一点透光的纸」
- **法线必须连同灯自转一起算**（`aAng + uRot`）：第一版忘了加，亮线和实际轮廓差一个随机角，
  灯就散成一团橙色噪点，怎么调都不像灯笼
- **灯芯不能贪亮**：给到 2.8 倍时八十颗小点叠成一块白斑，把好不容易算出的轮廓整个盖掉。现在是 1.45 倍、点也小一档
- **必须 `depthTest: false`**：树的针叶是写深度的实体点云，灯飘到树后会被整盏裁掉（第一版放完一轮一盏都看不见）
- **灯身剖面分两段**：底部开口略小 → 往上鼓到最宽 → 圆顶收到 0.34R 的小口。
  写成单条 `sqrt(1-u^2.3)` 时顶部收成 0.2R 的尖，投影上像蒙古包的尖顶
- **竖屏收窄半径**（`spread` 0.58）并减到 4 盏：可视宽度只有三分之一，六盏会挤成串
- 一轮升完（约 10.5 秒）之前不重复触发；手势一直比着也只放一轮
- 想直接看效果：页面里按 **`6`** 键

### 点赞 → 金箔纸屑

拇指竖起朝上、其余四指收起（`src/Confetti.js`）：一整棵树上撒下一层金箔，
每片翻转着往下落、落地前淡出，约 4.3 秒收完。

**为什么换掉原来的「五角星 + 666」**（旧实现留在 `LikeBurst.js`，没删）：

- **符号不对**。五角星属于「评分 / 收藏」那一套（打分、收藏夹、会员星级），
  放在雪夜圣诞树前面读起来像电商首页的角标；666 又是直播间用语。
  两个加在一起，情绪从「为你叫好」掉到「刷礼物」。
- **撒花不需要注解**。它是「叫好」最通用的视觉语言，一眼就懂，不用配字。
- **形态在场景里是独一份**：雪花是圆点、流星是斜线、孔明灯是球、螺旋是环，
  只有它是**薄片** —— 翻转时的宽窄变化让它和别的东西不会混。

**几处实现上的取舍**：

- **一片纸屑 = 一个点，形状在片元着色器里裁**。第一版用 4×2 共 8 个软圆点拼一片，
  跑起来全是「金色小点」：圆点没有边缘，8 个叠一起还是 8 个点，读不出「一张纸」。
  现在把 `gl_PointCoord` 转到片自己的坐标系里裁一个矩形，边是硬的、转动时有棱角，才像金箔。
  边缘只柔 20%～38%，再软就又变回圆点了。
- **点径要按视口换算，不能凭感觉**。顶点里是
  `gl_PointSize = L * DIAG * uSize / dist`，所以 `uSize = (viewportH/2) / tan(fov/2) / DIAG`。
  早先随手给 62，算下来一片只有 1.7 像素，等于什么都没画。
- **`DIAG` 不能省**：正方点要容下转到 45° 时的那条长边，否则斜着转的一瞬间两端会被裁掉。
- **不从一点炸开，按锥面散布**。试过「树腰一点迸发」，300 片挤在同一位置，
  加法混合下当场烧成一团白斑。改成按 `radiusAt` 的锥面散布、错开半秒出场，
  才像「一整棵树在往下撒」，也顺便让上下都有纸屑。
- **下落用 0.62 的重力**，不是 9.8。真实纸屑有空气阻力，落得慢；
  按真实重力算 1.7 秒就全落地了，来不及看。
- **落地要停住 + 淡出**：不止住会穿到地底下；不淡出会在地面留一层金屑停着不动。
- **竖屏另收一档**（片径 ×0.62、亮度 0.78→0.66）：树几乎占满窄屏，
  同样大小的片会连成一层白雾。
- 播完前不重复触发，手势一直比着也只撒一次。想看效果按 **`L`**。
- 判定用 `like` 分数（`_describeHand`），三个分量 + 两道闸门：

| 分量 | 含义 |
| --- | --- |
| `thumbOut` × 0.40 | 拇指尖离食指根多远（伸得开不开） |
| `fourCurled` × 0.32 | 食/中/无名/小指里「指尖不比 PIP 远」的比例 |
| `upness` × 0.28 | 拇指方向向量的 y 分量，判断是不是**朝上** |

乘上 `pinkyKeep`（小指伸出就把分数清零）和 `thumbGate`（拇指没伸出去就清零）。
实测拇指朝上 1.00 / 握拳 0 / 张开手 0 / 比 6 0 / 抓取 0，阈值 `0.70`。

- **`thumbGate` 是必须的**：握拳时拇指横搭在指头上，方向也是"朝上"（实测 `upness` 同样 1.0），
  只看方向会把握拳判成点赞，只有"拇指尖离食指根的距离"能分开这两者。
- **和「比 6」只差一根小指**：`pinkyKeep` 直接把小指伸出的情况清零；
  反过来 `_detectEvents` 里打电话那一轮会跳过 `like > 0.5` 的手 —— 点赞姿态在 `phone` 里也能攒到
  0.75，不让位的话比个大拇指会先飘出「孔明灯」。
- **只做金/银/香槟白，红只给 5%**：全给金色会和树上的暖白彩灯糊成一个色系，
  银给多了又会和雪分不开。金 46% / 香槟 22% / 银 14% / 暖橙 13% / 红 5%。
  描边只在下笔那条线上有点，密度集中、边界清楚 —— 一眼就认得出是星。
- **不用 emoji 字符**：`👍` 在 Windows / Android / iOS 是三套画法，个别环境只画方块，
  采样出来就是个矩形。星是用 canvas 几何画的（`drawStar()`：十点星形描边 + 中心亮芯），
  哪台机器上采样结果都一样。
- **粒子密度比亮度重要**：单点调亮只会得到一团白斑（泛光叠起来），
  正解是**加粒子、降单点亮度**（星 0.72 权重 / `gain` 2.4，共 9000 颗）。
- **背后垫一层软暗角**（`SoftVeil`，`max 0.42`）：星是「浮在树上的一层」，
  有暗角托着轮廓才立得住，同时不用把整棵树压暗。
- 想直接看效果：页面里按 **`L`** 键。

### OK → 爱心 · 流星雨 · 烟花 · miss you

单手比 OK（拇指食指成圈、另外三指伸开）触发一段 8.5 秒的独幕剧，时间轴在 `MissYou.js` 的 `TL`：

| 时间 | 发生什么 |
| --- | --- |
| 0.00 | 全屏爱心从外圈各自飞进来汇聚（0.75 秒成形），粉色描边 + 心口一点亮芯，成形后轻轻跳动 |
| 0.15 | 银色流星雨开始斜落，一直持续到 2.4 秒，每颗带一条拖尾 |
| 0.85 | 烟花从屏幕底部一发发射上去（5 发、间隔 0.26 秒），升空 0.52 秒后炸开成球、受重力下坠 |
| 2.55 | 爱心 / 流星 / 烟花**一起**被风吹散（同一套飘散公式，看起来是被同一阵风卷走） |
| 3.75 | 「miss you」用金色花体浮现 |
| 6.05 | 字也被吹散，整段结束 |

几个关键取舍：

- **为什么先散再出字**：满屏爱心和烟花还亮着的时候写什么字都看不出来。
  必须等画面空下来，字才有位置。
- **爱心只描边**：和「miss you」同一个理由 —— 加法混合下实心块会过曝成一块白斑。
  描边的墨迹集中在一条线上，粒子化之后轮廓反而更清楚。
- **心形里不套内圈**：试过在里面再画一个小一圈的心（想做出烫金压痕的层次），
  竖屏缩下来像「两个心叠在一起」，反而认不出是几颗心。改成心口一点亮芯。
- **心形的 y 轴只翻一次**：`16sin³t / 13cos t − 5cos2t − 2cos3t − cos4t` 是「y 向上」的
  数学坐标，峰值在 t≈±1（两个圆瓣）、谷底在 t=π（心尖）。canvas 的 y 向下，所以只在
  算 `py` 时减一次就够；多取一次负号整颗心就是倒的（这个坑踩过一次）。
- **流星拖尾要「连成线」**：拖尾 44 个点铺在 2.6~4.5 个单位上，屏幕上一单位约 80px，
  点间距 8px 左右刚好吃住；早先用 20 个点、间距近 20px，看起来是一串散点。
- **整段配一层全屏软暗角**（`SoftVeil`，`max 0.34`）：爱心和字都压在树上，
  不压背景根本立不住。暗角在 0.1 秒淡入、随字一起淡出，不会突然黑一下。
- **只在单手时判**：双手比心时两只手的 `ring` 也很高，混进来会把比心当成 OK，
  满屏爱心先把心形盖掉了。
- **和「捏合」的区别**只有一条：另外三根手指是伸还是屈。捏东西时手指多半收着。
- 冷却 9 秒（整段 8.5 秒），手势一直比着也只完整放一轮。
- 想直接看效果：页面里按 **`M`** 键。

第四行的 `电` 是打电话手势的实时分数、`赞` 是点赞手势的实时分数、`OK` 是单手 OK 手势的实时分数

## 场景氛围

这几层一直在走，和手势无关 —— 树静止不动的时候，画面里也得有东西在动。

### 绕树的暖金浮尘

`src/SpiralRise.js`，1100 颗粒子分三条臂，沿树的锥面螺旋上升，到树顶散开、底部再补进来，永远循环。

- **它退到背景里去了，这是故意的**：第一版是银白、1600 颗、浮在树外 0.52 米、亮度 0.85。
  结果它成了画面里唯一的高饱和冷色，又正好压在锥体的轮廓线上（人眼看锥体对比最敏感的
  位置），读起来像绕着一根绿柱子跑的灯带 —— 树从主角变成了灯带的柱子。
- **为什么换暖金**：这套画面深绿打底、暖金点缀（彩灯 `#ffd9a0`、树顶的星、孔明灯），
  银白是唯一的外来冷色，冷暖一撞就成了「第二个主角」。换成 `#ffc475`→`#ffedc2` 这一族
  之后，它不再是光源，读起来是树自己散出来的一点热气。
- **刺眼的是色相，不是亮度**：这一点做过三档实测（0.50 / 0.75 / 1.00）才确认 ——
  换成暖金之后，即便亮度回到 0.85 也不像原来银白那样抢（银白在深绿上是唯一的高饱和冷色，
  亮度只是放大器）。所以最终没把亮度压到看不见，定在 0.68（竖屏 0.54），
  「绕」这件事读得出来。中途试过压到 0.36，和关掉相比只差 1% 平均亮度，等于白开。
- **高度权重给宽一点**：`belly` 只留 0.40 的底（不是 0），覆盖根上方到树顶下方整段。
  收窄到「只在树腰」时，三条臂会在同一高度汇成一圈，看着像给树系了条金项链。
- **贴回树皮（+0.32）**：原来浮出 0.52，正好在轮廓线上（人眼看锥体时对比最敏感的位置）；
  0.16 又完全陷进针叶里只剩一片糊光。0.32 浮出半个身位，能看出「绕」又不压在轮廓上。
- **颗数 1600 → 1100**：太密会排成一条连续的线（像跑道灯），稀一点才像零散的光尘。
- **螺旋而不是直上直下**：直上直下就是一层雨，和场景里已有的飘雪打对台；
  反过来两股对流又太吵。螺旋自带「绕」的含义，贴着树的腰线走，像树自己在放光
- **半径跟着树轮廓变**（复用 `radiusAt` 那条锥线）：固定半径的圆柱螺旋
  在锥体旁边会「顶穿」—— 底部离树两米，到顶就飘在树冠外面
- **只做三条臂**：单臂只有一条线在转，看久了像根亮着的弹簧；三条错开 120°，
  任何时刻左中右都有粒子，缠绕感来自它们之间的关系
- **背向压暗（0.22 → 1.0）**：绕到树后面的那段必须暗下去。一开始前后一样亮，
  投影重叠之后就是锥面上撒了一把散点，完全看不出是缠绕
- **径向抖动只给 0.13**：抖到 0.22 就散成一圈雾，线就没了
- **它跟随树的旋转与缩放**（`params.spin` / `params.scale`）：树被扇着转、被双手放大时，
  光带得跟着一起，否则会脱开

要是哪天觉得它还是多余，`main.js` 里把 `new SpiralRise(...)` 那一行删掉就行 ——
别的东西都不依赖它。

调参：粒子数在 `main.js` 的 `new SpiralRise(...)`，绕几圈是 `TURNS`，臂数是 `ARMS`，
亮度是 `uIntensity`（默认 0.68，竖屏 0.54），点径是 `uSize`（默认 38，竖屏 29）。

### 雪

`src/SceneEffects.js` 里 1000 颗粒子往下落，比心时从冷白渐变到玫瑰粉（`uLove`），
侧掌扇风时被横向吹偏（`uSwirl`），拍手时变成暴雪（`uStorm`）。

### 树底：发光地台 + 星云底座

`src/GroundBase.js`。原来的树底只有一块近乎全黑的地面 + 一张半径 8.5 的绿色光贴片，
礼物盒看着全在「飘」——虽然它们的 y 一直是半个盒高、正好贴地。**「站在地上」这件事
靠的是它和地面的接触关系**，不是它自己的阴影。所以这里补齐四层，各管一件事：

| 层 | 参数 | 作用 |
| --- | --- | --- |
| 地灯 | 3 × `PointLight`，`(14, 11, 2)` | 地面的明暗由它算，礼物盒侧面也被点亮 |
| 暖光池 | `warmPoolTexture()`，加色，r≈4.3 | 树脚那一圈被照亮的雪 |
| 绿色回光 | `canopySpillTexture()`，环状，r 3~7 | 冷暖交界，地面才和树连成一体 |
| 星云 + 光雾 | 1150 颗上浮粒子 + 69 团大而极淡的柔光 | 给底座厚度，纯贴片永远是一张纸 |

踩过的坑，改的时候别踩回去：

- **峰值不能在正中心**。树站在中间，r < 2.6 全被针叶挡住，中心再亮也看不见。
  第一版按「中心最亮、往外衰减」做，露出来的只剩 r > 2.6 那段已经很暗的尾巴，
  读起来就是地上糊了一片暖灰。把峰值挪到 r 2.3~3.0（树根和礼物堆那一圈）才对。
- **加色贴片自己撑不出一块地**。它没有法线，从低角度看永远是一条横向雾带。
  真正的明暗来自漫反射，所以必须有三盏真实点光 —— 而且 three 现在按物理量走
  （坎德拉），`intensity` 给 1 完全看不见，照度 = `intensity / 距离²`，
  想在地面上拿到 0.3 左右的亮度得给到十几。
- **地面反照率不能太黑**。`0x0c141d` 那个程度上，任何灯打上去都是「黑上加点亮」，
  看着像贴了一层雾；抬到 `0x1c2632` 才有「雪被照亮」的漫反射底子。
- **画框底边就是 r≈3.9 的地面**（相机 42° 视野、几乎平视）。所以半径越大，
  可见的渐变越被压成一条横带 —— 光池半径拉到 11 的那一版看起来像一片沙丘。
- **投影要往外拖**。第一版是贴着盒底的一圈接触阴影，1440 宽上只有七八个像素，
  等于没画；而且盒底被地灯照亮、比地面还亮，眼睛只会得出「悬空」的结论。
  现在按「灯在树心」的方向往下拖成 1.58 : 1.34 的椭圆，影子落在盒子外侧看得见的雪上。
  它的 `renderOrder` 必须是 3（大于两层加色光的 1），否则光会把影子吃掉。
- **雾要「单团几乎看不见」**。几十团直径 40~120 像素、单团不透明度 0.05 左右的大柔光，
  叠起来才有地雾的厚度；任何一团能单独看出形状，就变成一颗颗球了。

调参：光池亮度/半径在 `update()` 的 `poolMat.opacity` 与 `_buildPool()` 里的
`PlaneGeometry(8.6, 8.6)`、梯度在 `textures.js` 的 `warmPoolTexture()`；地灯在
`_buildBaseLights()`（色温 `0xffd0a2`、强度 14）；粒子数与雾的团数在 `main.js` 的
`new GroundBase(...)`；雾的浓度是顶点着色器里的 `0.042`。

### 树底频谱水波纹（已关闭）

`src/SpectrumRipple.js`——**目前整体关闭**（`main.js` 里的 `RIPPLE_ENABLED = false`，
实例化、每帧更新、resize、W 键演示全部判空跳过；想恢复改回 `true` 即可，
`main.js` 底部按 **W** 还能不依赖音乐单独演示）。关闭后树底只剩暖光池。
下面保留当初的实现要点：平铺在树底地面上，**整体必须淡**——只是一层微光，不抢树：

- **频谱环两层**：外圈（半径 4.55，光池峰值圈外一点）每个角度的外扩量由频谱
  驱动，满格外扩 1.35；内圈（3.45）是更矮更淡的倒影层（幅度 0.7、亮度 0.22 档），
  错开半个采样步避免两层点重合。频谱 64 点按**左右对称**铺——`|θ|` 相同的
  角度取同一个频点，画面永远轴对称。
- **鼓点涟漪**：每次鼓点（`beat.hit`）从 r≈3.1 向外扩一道圆环，2.6 秒扩散到
  r≈8.6、越扩越淡。最多同时 3 道，循环复用。**只跟真音乐走**——待机的
  96 BPM 假鼓点不触发，否则树底会常驻一个涟漪。
- **不是常驻的**：整层有总开关 `uMaster`，有频谱 ~1.2s 淡入；音乐暂停 /
  没放歌 / 跨域读不到频谱时 ~3s 淡淡消失（无音乐时不做假波，安静退场）。

数据链路：`AudioEngine.getFrame()` 在四个频段之外额外输出 64 点**对数分布**
频谱（55Hz~8.2kHz，每点取频段内最大值，0..1）→ `ripple.update(t, spectrum, beat, dt)`
写进 `uSpec[64]` uniform → 顶点着色器按角度线性插值取值算半径。
整层全 GPU，每帧 CPU 只写 64 个 float 和 3 个涟漪起始时间。

踩过的坑：

- **倒写 `smoothstep(0.5, 0.10, x)` 是未定义行为**，有的驱动上圆形遮罩直接
  失效、点精灵渲染成方块。必须写 `1.0 - smoothstep(0.10, 0.5, x)`。
- **自定义 uniform 数组必须在着色器源码里声明**——第一版在顶点着色器里用了
  `uRippleStart[]` 但忘了写声明行，编译失败、整圈静默消失且无 JS 异常。
- **点径必须大于点间距**：周长 28.6 / 260 点 ≈ 0.11，点径 0.10 时看着是一串
  珠子；260 点 + 点径 0.11 起才连成连续水波。第一版点径 0.17 + 亮度 0.75 档
  太粗太亮，用户反馈「太明显」，压到 0.11/0.55 档才像淡淡的水痕。

调参：环半径/幅度是文件头的 `RING_R`/`RING_IN`/`RING_AMP`，淡入淡出速度在
`update()` 的两处指数系数（淡入 2.6 / 淡出 0.9），涟漪速度与寿命是
`RIPPLE_SPD`/`RIPPLE_LIFE`，频点范围在 `_spectrumRanges()` 的 `lo/hi`。

## 音乐

进页面会自动载入一首默认曲（地址在 `src/appConfig.js` 的 `DEFAULT_MUSIC`，换成自己的改一行）。
点「放入音乐」选文件，或直接把音频拖进窗口，会覆盖默认曲。

浏览器一律禁止「用户没点过就出声」，所以载入之后**不会**偷偷自动播放：
底部会亮一个「♪ 点击播放音乐」胶囊（手机上改为给顶栏的「播放」按钮描一圈金边），
点了才响。整个应用里任何一次点击/按键都只负责恢复 AudioContext，开播必须由用户明确点。

**首屏先听**：首帧画完之后，加载遮罩底部浮上一张确认卡「先听一首歌？ / Enjoy some music?」，
两个按钮都是中英双行（`开启音乐 / Play`、`先不用 / Not now`）。点「开启音乐」才开始取音频
（不点就不抢模型的带宽），按钮上直接显示「正在载入 43% / Loading」，取完自动关卡片并播放。
点「先不用」就彻底不打扰，遮罩收起后照常亮底部胶囊。卡片靠下摆放，上方那半留给了加载进度，
不把中英状态行和进度条盖住。

卡片挂在 `#loading` 外面（`z-index:40`）：本地秒开时遮罩一秒就收，卡片还能留在场景上等一个答复。
没人理会在 12 秒后自己收；用户点了「开启音乐」/「先不用」立刻收；卡片在的时候底部胶囊先让位。

音频只驱动**亮度、Bloom、粒子脉动、装饰球自发光、雪花扰动**，不改变形态——
手势与音乐分别控形与控能，互不覆盖。没有音乐时使用内置 96 BPM 律动，画面不会静止。

### 音乐是流式播的，不是「下完再播」

一首 2–3MB 的歌，如果先整首 `fetch` 回来、`decodeAudioData` 解完再播，
在慢网上就是「点了没声，十几秒后才响」，甚至永远等不到。
现在的做法是**边下边播**：把 URL 直接挂到 `<audio>` 上，只等 `loadedmetadata`
（文件开头几十 KB），点一下立刻出声，剩下的字节浏览器按 `Range` 自己往后拉。

实测（限速 300KB/s 的模拟 CDN，40 秒 / 1.76MB 的文件）：
元数据 **652ms** 就到，此时只缓冲了 5.2 秒，播放已经在走 —— 不等整首下完。

三条路，按「快 → 稳」依次尝试：

| 顺序 | 走哪条 | 频谱 | 说明 |
| --- | --- | --- | --- |
| 1 | 直连 + `crossorigin="anonymous"` | ✅ | COS / 任何配了 CORS 的 CDN。少一跳，最快 |
| 2 | 同源代理 `/__audio`（`serve.py`） | ✅ | 源站没发 CORS 头时的兜底。代理透传 `Range` 且 64KB 边收边发，**仍然是流式** |
| 3 | 裸直连（不带 crossorigin） | ❌ | 能出声，但元素被污染读不到频谱，呼吸退回内置节拍 |

- 单条路 8 秒超时，整体 14 秒；5 秒还没元数据，界面会写「网络较慢，仍在连接…」，
  把「在等」和「卡死」区分开。
- 并发保护：新的加载会立刻作废上一条（令牌 `_seq`），不会出现两条请求互相拆元素、
  白等 15 秒超时的情况。
- 本地拖进来的文件仍然走整首解码：读盘是毫秒级，换来的是无缝循环和精确定位。

默认曲要**第一次点击 / 触摸 / 按键后**才出声——浏览器的自动播放策略不允许页面自己开声音。
按钮文字会从「播放」变成「暂停」，说明真的响了。首屏那张「先听一首歌？」卡片就是最省事的那一次点击：
点了就连接、就绪就播；流式下拿不到「下载百分比」，所以按钮只报「正在连接…」，不编数字。

### 换成腾讯云 COS 之后

COS 走 CDN 边缘节点，首字节通常 20–100ms，一首 2–3MB 的歌基本是秒开；
而且原生支持 `Range`，天生适合流式。但**必须在存储桶上配 CORS**，否则第一条路会被拦。

控制台 → 存储桶 → 安全设置 → 跨域访问 CORS，加一条规则：

| 项 | 值 |
| --- | --- |
| 来源 Origin | `https://你的站点域名`（本地调试再加 `http://127.0.0.1:8123`） |
| 操作 Methods | `GET`、`HEAD` |
| Allow-Headers | `*`（至少要有 `Range`） |
| Expose-Headers | `Content-Length`、`Content-Range`、`Accept-Ranges` |
| 超时 Max-Age | `600` |

配完自检两条命令：

```bash
curl -I 'https://你的桶.cos.ap-guangzhou.myqcloud.com/christmas.mp3'
# 期望看到：Content-Length / Accept-Ranges: bytes / Content-Type: audio/mpeg

curl -I -H 'Origin: http://127.0.0.1:8123' 'https://你的桶.cos.ap-guangzhou.myqcloud.com/christmas.mp3'
# 期望看到：Access-Control-Allow-Origin: http://127.0.0.1:8123
```

然后把 `src/appConfig.js` 里的 `DEFAULT_MUSIC` 换成 COS 地址就行（其它都不用改）：

- 用**公共读**桶，别用私有桶的签名 URL —— 签名会过期，过几天就播不了。
- 建议 `m4a/aac 128kbps` 或 `mp3 96–128kbps`，三分钟约 2–3MB。
- 文件名带版本号（`christmas-v2.mp3`）方便刷 CDN 缓存；COS 默认 `Cache-Control` 建议
  `public, max-age=86400`，别用 `no-cache`。
- 如果 COS 前面还挂了自定义域名 + CDN，注意别把 `Range` 头过滤掉。

没配 CORS 也能用，只是会退到第 2 条（本地代理）或第 3 条（裸直连）：
前者多一跳、只在本地 `serve.py` 下存在；后者能出声但画面呼吸改用内置节拍。

### 该放什么格式

**mp3 或 m4a(aac) 最稳**，wav / ogg 也可以。建议 3–5 分钟、20MB 以内。

`AudioEngine` 有两条路径：

| 模式 | 用在哪 | 特点 |
| --- | --- | --- |
| `element` | **远端 URL 一律走这条** | `<audio>` + `MediaElementAudioSourceNode`，边下边播，内存几十 KB |
| `buffer` | 只给本地拖进来的小文件（≤ 20MB，触屏 9MB） | `decodeAudioData` 整首解码，循环无缝、定位精确 |

远端为什么不 `decode`：手机上解码一首 5 分钟的歌要占约 100MB `AudioBuffer`，
Safari 经常直接抛错或者整页崩掉；而且必须先下完整个文件才能解码——那正是「加载很慢」的根源。

### 手机上为什么选不到文件

文件选择器是系统给的，浏览器只能要求「音频」，给不了绕过办法：

- **iPhone**：要从「文件」App 里选。QQ 音乐、网易云、Apple Music 里下载的曲子带版权保护
  （DRM），系统不允许任何网页读取，所以在选择器里是灰的点不动——不是本项目的问题。
- **微信内置浏览器**：基本不允许选择文件，需要点右上角「…」→ 在浏览器中打开。
- **安卓**：用文件管理器选，不要从「音乐」App 里选；部分厂商浏览器的选择器只给图片。
- **转换**：实在不行用电脑或格式转换工具另存为标准 mp3（44.1kHz / 立体声）再传进来。

页面右上角的 `?` 按钮里有同样的说明；选到不支持的格式时，状态条会给具体原因。

## 调参

- 粒子数量与配色：`src/ParticleTree.js` 顶部常量与 `_buildNeedles()`
- 树形轮廓：`radiusAt(t, angle)`，控制锥度、分层幅度与不规则起伏
- 明暗与体积：针叶着色器里的 `lam` / `topLight` / `back` / `fillL`。
  其中 `fillL` 是**朝相机的补光**——树会自转，转到背光角度时如果没有它，
  那一面会整片变黑，只剩彩灯浮在空中。改 `back` 的 0.48 调背面压暗强度。
- 手势灵敏度：`src/GestureController.js` 的 `sideW` 曲线（扇风）、开合阈值、拍手距离
- 旋转手感：`src/InteractionRouter.js` 顶部的 `SPIN`（`rate` 扇多快转多快、`dead` 死区、
  `friction` 松手后转多久、`sideGate` 门控）
- 缩放与回弹：`src/InteractionRouter.js` 的 `scaleVel` 弹簧参数
- 呼吸曲线：`src/BreathMapper.js` 的 `base / music / breath` 三项权重
- 心形大小与亮度：`src/HeartEffect.js` 的 `HEART_Z`（远近）、`uSize`（粒子尺寸）、
  `glowMat.opacity`（中心柔光）
- 比心灵敏度：`src/GestureController.js` 顶部的 `HEART_CFG`（`ring` 门槛、`gap` 区间、保持时长）
- 拉弓灵敏度：`src/GestureController.js` 顶部的 `BOW_CFG`（`start`/`full` 拉伸区间、`drop` 放箭阈值、`gripMin` 握姿门槛、`cooldown`）
- 拉弓外观：`src/BowArrow.js` 的 `BOW`（弓的凸度 `depth`、弓梢后仰 `tipBack`、弦的行程 `pullMax`、
  心的大小 `heartWide`/`heartNarrow`）、`_layout()` 里三个位置系数（右下 / 左上 / 弓的大小）、
  粒子数 `N_BURST` 与配色 `palette`
- 孔明灯：盏数与粒子数在 `main.js` 的 `new WishLantern(...)`、灯身尺寸 `LANTERN_H` / `R0`、
  上升速度与错开间隔在 `WishLantern.js` 的 `_layout()`、竖屏收窄系数在 `update()` 的 `spread` 目标值
- 螺旋浮尘：绕几圈 `TURNS`、臂数 `ARMS`、亮度 `uIntensity`（默认 0.68，竖屏 0.54）、点径 `uSize`
  （38 / 竖屏 29）、离树皮多远在顶点着色器里那个 `+0.32`
- 树底地台：光池梯度在 `textures.js` 的 `warmPoolTexture()`（峰值必须落在 r 2.3~3.0）、
  池半径在 `GroundBase._buildPool()` 的 `PlaneGeometry(8.6, 8.6)`、亮度与地灯强度在 `update()`、
  地灯色温/距离在 `_buildBaseLights()`、投影的偏移与椭圆比在 `groundShadow()`
- 暴雪快捷键：`main.js` 底部的 `keydown` 监听 —— 按 **S** 直接触发一次拍手爆雪
  （走和真手势同一个 `handleGestureEvent` 入口，HUD 提示也会亮）。连按只是把衰减
  曲线拉回峰值，不会叠成双重爆炸。其它调试键：**B** 拉弓演示放箭、**T** I love you、
  **6** 孔明灯、**M** OK 全段、**L** 纸屑、**W** 水波纹演示、Ctrl+Shift+D 探针开关
- 水波纹排障：按 **W** 切换演示模式——不依赖音乐，直接喂假频谱 + 96 BPM 假鼓点。
  演示模式下树底水波正常 = 特效没问题，问题在音频链路；同时把链路状态
  （`mode / playing / analysable / ctx / levels`）打进控制台和底部提示条。
  常见情况：流式跨域没 CORS（analysable=false）、AudioContext 未恢复（ctx=suspended）、
  没点播放（playing=false）——这三种 `getFrame()` 都拿不到频谱，水波按设计淡出
- 清屏（录屏演示）：右上角音乐条里的 **⛶** 按钮 —— 一键淡出标题、控制栏、摄像头、
  玩法一览、底部提示、接礼物计数、拉弓进度，画面里只剩树和特效。清屏瞬间顶部居中
  弹一条 2 秒的轻提示「右下角图标可退出」，之后自己淡掉。恢复入口：**右下角极淡的
  ☰ 图标**（opacity 0.22，鼠标碰上才亮，录屏里几乎看不见）或 **Esc**。
  **⛶ 与 ☰ 都是纯图标，不参与翻译**（字典里没有它们的文本 key，切换语言不受影响）。
  样式在 `styles.css` 的 `#hud.clean …` / `.clean-toast`，逻辑在 `main.js` 的 `setClean()`
- 语言切换：首屏遮罩上有 **中文 / English / ไทย** 三按钮；进入内容页后右上角音乐条
  里的 **语言按钮**（显示 `中 / EN / ไท`，点击循环）随时可切。两者走同一个
  `switchLanguage()`：`setLang()`（存 localStorage `tree.lang` + 刷静态）→
  `refreshDynamicTexts()`（播放按钮、曲名区、音乐弹窗三态、摄像头占位、拉弓提示、
  底部玩法提示全部按新语言重画）。动态文案的写入必须走 `setTrackLabel()` /
  `setPromptButtons()` 这类「记 key 不记字符串」的辅助函数，否则切语言后残留旧语言。
  曲名区 title、默认音乐标题等也全部 key 化（`trackTitle.*`）
- 前景失焦光斑：**已移除**（`NearBokeh.js` 已删，见「前景：失焦光斑（已移除）」一节）
- 打电话手势阈值：`_detectEvents` 里 `h.phone > 0.72`，探针第四行的 `电` 是实时分数
- OK 手势阈值：`OK_CFG.threshold`（默认 0.62）、节奏在 `MissYou.js` 顶部的 `TL`（成形 / 停留 / 吹散 / 出字时间）
- 点赞手势阈值：`LIKE_CFG.threshold`（默认 0.70，探针 `赞` 是实时分数）、
  纸屑在 `Confetti.js`：片数在 `main.js` 的 `new Confetti(...)`、片长 `L`、宽长比 `ASPECT`、
  下落重力与风力在顶点着色器、寿命 `LIFE`、配色 `PALETTE`
- 文字可读性：中文 `height`（字格高）调大 + 粒子数调高最有效；暗角在 `SoftVeil` 的 `max`
- 首屏进度：权重在 `src/main.js` 的 `BOOT_W`（35/30/35，慢网可把 model 调大）；
  数字补间系数 `stepPct()` 的 0.17；手势链路的估算斜率在 `paintLoading()` 里 `/ 4` 这个数；
  跳过按钮延迟 `SKIP_AFTER`、总超时 `READY_WAIT`；扫光/流光周期在 `styles.css` 的
  `bar-shine` / `bar-wait`。`?debug` 下 `window.__app.bootState.dbg` 里能看到进度条的逐帧拆解

## 注意

- 摄像头需要 `localhost` 或 https，直接双击 `index.html` 不行
- 亮度、Bloom、粒子尺寸都已 clamp，鼓点不会把画面冲爆
- 手机通过局域网 IP 访问时是 http，浏览器会禁用摄像头（需要 https）；画面与音乐仍可用
- 在 URL 后加 `?debug` 会暴露 `window.__app`，`performance.getEntriesByType('measure')`
  里能看到 `mp:wasm` / `mp:init` 耗时
