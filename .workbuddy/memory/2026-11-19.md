# 2026-11-19

## MediaPipe Hands + Three.js 手势圣诞粒子树（从零搭建）

**目标**：粒子圣诞树 + 手势交互 + MP3 音乐驱动呼吸，三层解耦（形态/能量）。

**架构**（src/）：
- `ParticleTree.js`：26k 针叶粒子（自定义 ShaderMaterial，程序化针叶纹理 + 旋转 UV）、
  1500 光尘、190 螺旋彩灯、30 个 InstancedMesh 金属装饰球、LatheGeometry 树体、Sprite 树顶星。
- `GestureController.js`：MediaPipe HandLandmarker（本地 wasm + 模型），输出 palm/openness/pinch/palmUp，
  事件 burst / clap / tray。
- `AudioEngine.js` + `BeatDetector.js` + `BreathMapper.js`：分频段 FFT → 鼓点 → 亮度/Bloom/暖色。
- `InteractionRouter.js`：手势控形（scale/collapse/explode/swirl），音乐控能，相加后 clamp。
- `GiftRain.js`：掉落礼物 + 托盘接取 + 金色爆散。

**关键经验**：
1. 粒子"没有体积"的根因不是数量，而是缺伪光照 + 背面压暗。着色器里用径向法线做 lambert、
   按 hN 做高度衰减、按 p.z 做背面压暗（×0.32），体积感立刻出来。
2. 实心锥体会从粒子壳的低谷处穿出来，形成黑色横带 → 改用 LatheGeometry 跟随 `radiusAt()`
   分层曲线，并缩到 0.84 倍藏在壳内。
3. 加法混合会累积饱和度，光尘/雪花的亮度必须压到 0.5~0.9，否则整棵树糊成"雪球"。
4. 鼓点检测不能用单频段绝对阈值：频谱平滑会把一次底鼓拖成连续触发。
   改成 `score = low*0.7 + rms*0.9` + 最近 1s 均值/标准差自适应阈值 + 200ms 冷却 + 重新武装，
   60fps 合成信号下 BPM 估算准确（96→96）。
5. 预热条件不能写 `history.length > N`（帧率低时永远不满足），要改按时间 `now - startAt > 600`。

**踩坑**：jsdelivr 下载 wasm 会被截断（7.2MB vs 9.4MB），WebAssembly 报 "section extends past end"，
必须校验 Content-Length。所有依赖已本地化到 `vendor/`，断网可跑。

**运行**：`start.bat` 或 `python -m http.server 8123`，摄像头需 localhost/https。
`?debug` 暴露 `window.__app`。

## 树顶星重做（11:45）

原来的 `starTexture` 是 4 根楔形尖刺拼出来的，加法混合 + Bloom 之后糊成不规则白斑，不成立。
改为：**五角星本体（NormalBlending）+ 独立辉光层（AdditiveBlending）**，两张 sprite 叠在一起。

- 本体 `textures.js: starTexture()`：按 5 根臂 × 2 个切面分别计算明暗（法线朝光程度），
  天然形成折脊；再叠左上柔光 sheen、折脊高光、单侧轮廓 rim（只亮受光侧）、中心反光点。
  颜色在琥珀(196,108,26) ↔ 淡金(255,220,166) 之间插值，白色只留给高光。
- 辉光 `starGlowTexture()`：星形模糊 + 圆形柔光，单独一层加法混合，scale 2.75（受 beat 涨到 3.3）。
- 动画：`rotation = sin(t*0.28)*0.05` 极缓摇摆（原来是 t*0.12 匀速转，像风车），
  亮度用 `0.965 + 0.035*sin(t*1.15)` 的慢呼吸，不再随鼓点大幅跳变。

**关键教训**：加法混合会把暗部直接吃掉，所以任何"要有体积感"的贴图都不能用 additive 画明暗，
必须实体用 Normal、辉光单独一层 additive。另外小尺寸 sprite 贴图要开 mipmap，否则缩放时边缘闪烁。

**验证**：headless 截图 + 程序化检查，beat=1 时 bodyScale 2.05→2.255、glowScale 2.75→3.3、
opacity 0.881→0.961，无 pageerror。

## 加载速度优化（12:30）

**实测定位**（headless + 软件渲染，localhost）：
- 旧流程：页面到可用 2.8s，其中主线程长任务 552ms + 764ms（建树 + 首帧着色器编译），
  模型下载在首帧之后才开始，且 wasm(9.2MB) → 模型(7.6MB) 严格串行。
- 真凶其实不是"模型慢"，而是：① 明文传输 18.7MB；② 串行；③ 网络请求被首帧渲染饿死。

**改法**：
1. `serve.py`（新）：gzip + immutable 缓存头 + 正确 MIME。wasm 9.4→2.9MB、模型 7.8→5.9MB、
   three 1.27→0.26MB，首次总传输 18.7MB → 9.0MB。`start.bat` 改用它。
2. `src/assetLoader.js`（新）：模型用 `modelAssetBuffer` 自己下（带进度），走 IndexedDB
   (`mp-model-cache`) 缓存 → 第二次打开零请求；local/cdn 双源 + 任一失败自动切换；
   按 `?src=` 选源，localhost 默认本地、其它域名默认 auto。
3. `GestureController`：`getUserMedia` 与 `createFromOptions` 并行；delegate 上次成功结果存
   localStorage，避免移动端每次先试 GPU 再退 CPU。
4. `main.js`：预取提前到场景构建之前；首屏渲染完立刻收遮罩，模型在后台继续（原来要等摄像头就绪）；
   `isSecureContext` 为 false 时**完全跳过模型下载**（手机 http 局域网开不了摄像头，9MB 纯浪费）。
5. 低功耗档位：`configureQuality()`，触屏/≤4 核时针叶 26000→16000、像素比 1.5。

**注意**：`performance.mark('mp:wasm' / 'mp:init')` 留在代码里，`?debug` 下可直接看阶段耗时。
测得 init 约 370ms、wasm 缓存命中 7ms，剩余主要成本是首帧着色器编译（软件渲染 800ms，真机 GPU 小得多）。

## 音频双模式 + 双手比心（19:10）

### 1. 音频：为什么手机上 mp3 导不进来
两条独立原因：
- **选不到**：iOS 从「音乐」App 里的曲子是 DRM 的，文件选择器里是灰的；微信内置浏览器基本禁止选文件。
- **解不开/内存炸**：只有 `decodeAudioData` 一条路时，5 分钟歌 ≈ 100MB AudioBuffer，Safari 直接抛错或崩溃。

改法（`src/AudioEngine.js` 重写）：
- `decodeLimit()`：≤20MB（触屏 9MB）走 buffer 整首解码；否则或解码抛错 → **element 流式模式**
  （`<audio>` + `MediaElementAudioSourceNode` → gain → analyser），内存只有几十 KB。
- 错误按 `code: 'empty' | 'unsupported'` 分类，`main.js: audioErrorText()` 给具体人话提示。
- 加了 `?` 帮助气泡（`#btnHelp` / `#musicHelp`）、`accept` 白名单、桌面拖拽导入、微信 UA 提示。
- 窄屏（≤760px）隐藏 `.track`，曲名改在底部状态条显示。

**注意**：element 模式必须 `ctx.resume()` + 由用户手势触发 `play()`；headless 下 blob 取 metadata
偶尔要 1–2s，超时设了 10s，真机很快。

### 2. 双手比心（不用单手）
单手比心 = 拇指食指交叉，和「捏合」几何同构，640×480 下指尖并成一团 → 误触率高。
双手比心多约束：两手各自 `ring > 0.55`（拇指尖-食指尖闭合）、`gap`（两手 tipMid 间距 / 手宽）
在 0.45–3.8、等高 `level < 1.35`、稳定 180ms，且拍手后 420ms 内抑制。
`GestureController._computeHeart()` 输出连续值 `{active, strength, x, y, radius}`（归一化、已镜像）。

### 3. 心形光尘（`src/HeartEffect.js`）
- 1600 颗粒子：52% 沿心形曲线、48% 用拒绝采样填内部；**轮廓按弧长采样**，
  否则心尖处导数趋零会把粒子挤成一团亮斑（第一版就是这个坑）。
- 尺寸不能全用同一种：轮廓 0.8–1.95、内部 0.38–1.0 且压暗到 0.4，轮廓另有 7% 高亮火星。
- 三层：dust（加法混合自定义着色器）+ glow sprite（opacity 0.17，别超过 0.25 否则糊成粉雾）+ floaters
  （16 颗心形贴图小爱心，uSize 104，纹理外发光必须克制在 blur 2.4，否则 12px 下就是光斑）。
- 反投影：`ndc.unproject(camera)` → 与 `z = HEART_Z(5.6)` 平面求交，得到世界坐标；
  radius 用左右两点投影差换算世界尺寸，随窗口/机位自动适配。
- 心跳包络双峰 `exp(-((p-0.02)*11)^2) + 0.62*exp(-((p-0.2)*13)^2)` 驱动缩放；松手 `rise` 上浮淡出。
- 联动氛围：`router.love` → Bloom +0.18、warm +0.22、雪 `uLove` 变玫瑰粉并减速、地面光晕转粉、心口粉色点光。

**验证**：合成手势正负样本（正常比心 active/0.83，张开手掌、两手叠一起、单手、刚拍手均不触发）；
桌面/移动截图；无 pageerror。

## 比心与双手捏合冲突修复（21:40）

**现象**：用户真机反馈「双手比心和双手捏合冲突，一次也没出过比心」。

**根因**（三条叠加）：
1. `ring` 门槛太严：`ring = 1-(pinchRaw-0.14)/0.38`，`>0.55` 要求拇指-食指距离 < 0.31 手宽。
   真人比心指尖常留 1–2mm 缝，640×480 下直接判负。
2. `gap > 0.45` 下限把「两个圈相贴」的标准比心挡在门外（比心 gap 常在 0.3–0.6）。
3. `InteractionRouter` 无条件用 `spread` 驱动缩放：做比心时两手靠近 → 树被抽小，
   即使心形亮了也被缩放的视觉盖住；同时 `_detectEvents` 的拍手判定（spread<0.16）会误触发爆雪，
   并顺带抑制 300–420ms 的心形判定。

**改法**：
- `_describeHand`：`ring = clamp01(1-(pinchRaw-0.30)/0.85)`（≤0.30 满分、1.15 归零）；
  新增 `pinchRaw`、`indexStraight`（食指伸直度，仅作 0.85 权重微调，不做硬判）。
- `_computeHeart` 重写为**软打分**：`score = ringScore * gapScore * levelScore * rateScore * straight`，
  新增到 `HEART_CFG`（文件顶部统一放阈值）：
  gap 0.16–1.30 满分 / 1.90 归零；level ≤0.85 / 1.60；rate（手指尖间距变化速度，手宽/秒）
  ≤2.5 / 5.0；保持 260ms 点亮、松手 220ms 滞回熄灭；拍手抑制 300ms。
- **gap 两级平滑**（`gapSmooth 0.30`、`rateSmooth 0.30`）：不先低通就算速度，摄像头逐帧抖动
  会被当成「手在动」→ 比心永远点不亮（这是最容易被忽略的坑）。
- **缩放让位**：`InteractionRouter.update()` 把 love 提前到缩放之前，`spreadW = 1-clamp(love*2.4)`，
  比心期间树定住；UI 高亮里 `spread` 在 love>0.25 时不再亮。
- **拍手不误伤**：`_detectEvents` 里 `bothRinged`（两手 ring>0.5）时不算拍手。
- **探针**：`?debug` 或 `Ctrl/⌘+Shift+D` 显示 `手/圈/距/平/速/分/心 · stage`，
  stage 直接指出卡在哪（hands/ring/near/far/level/move/hold/clap/on）。样式见 `styles.css` `.probe`。

**验证**：`node` 直接 import 源码（把首行 import 换成 null 占位）做单测 +
CDP 连无头 Chrome 在真实页面里跑 `_computeHeart`：
静置比心 on(0.99)、拉拽缩放 far、两手张开 ring、错位 level→far、恢复比心 on；无 pageerror。

## 比心结束 → 粒子拼字 I love you（22:20）

**需求**：爱心结束时没有收尾，希望心散成粒子 → 拼出 "I love you" → 停留几秒 → 文字随风飘散。

**新增 `src/LoveMessage.js`**（2200 粒子 / 低功耗 1200）：
- **字形采样**：离屏 canvas 1024×300，`italic 700 Georgia/"Times New Roman"/Songti SC`，
  按 alpha>130、step=2 采样像素点，归一化到 TEXT_W=8.8 世界宽。
  （字体自适应：先按 0.72H 画，量宽度超 92% 再等比缩字号。）
- **起点连续性**（关键）：`HeartEffect` 构造时接 `onEnd(pos, scale)`，心形 `strength`
  从 >0.6 掉到 <0.45（+1.6s 冷却 + intensity>0.35）时把心形世界位置与缩放传出去，
  粒子用 `aFrom = heartPoint(t) * k`（60% 沿轮廓、40% 内部 sqrt 采样）原地起飞。
  **不要**让文字单独淡入 —— 观感会变成"两个特效"。
- **飞行**：`local = (uFly - aDelay)/(1-aDelay)`，aDelay 0–0.38 随机，smootherstep 缓动，
  叠加 `sin(π·e)` 上抛弧线 + 侧向随机偏移，避免整体平移。
- **风散**：`wave = smoothstep(0, 1, uDissolve*1.45 - (x+3.7)*0.058)`，
  越靠右越晚吹走 → 从左到右一道波浪；方向 `(0.85+seed*0.85, 0.34+seed*0.6, 0.18)`。
- **字幕让位**：`LoveMessage.dim`（fly/hold 为 1，blow 随 dissolve 退，6/s 平滑），
  main 里 `params.brightness *= 1-0.13*dim`、`bloom *= 1-0.08*dim`。
- 竖屏用相机 fov/aspect 反算可视宽度，`uTextScale = min(TEXT_W, availW)/TEXT_W` 防溢出。
- 再次比心 `cancel()` → 直接跳到 blow 45% 处。

**踩坑**：文字第一版 y=5.42 + 色 ×2.5 时被树腰的彩灯淹没（加法混合同亮度区），
上移到 6.02、色提亮到 ×3.1/×3.7 并压暗树 13% 后才"跳出来"。
`dt * 0.0` 那行（想写"透明度由 wave 负责"）是废码，已清。

**验证**：CDP 无头 Chrome 走真实链路（heart.update 亮起→衰减）确认自动触发 fly；
截图 hold 帧字形清晰可读；blow 帧呈右上星尘云、左侧先空；无 pageerror。

### 修「没看到文字」
**根因**：`HeartEffect` 用 `prevStrength > 0.6 && strength < 0.45` 判定心形熄灭 →

## 画圈/推拉 → 侧掌扇风 + 左右滑树（22:40）

**需求**：画圈推拉判不准，改成「手掌竖着（掌心朝左/右）+ 左右扇风 → 树左右滑动」，滑动要防抖。

**判定（`GestureController._describeHand`）**：
- 复用掌心法线：`sideW = smooth((|nx|-0.40)/0.28) * (1-smooth((|ny|-0.45)/0.30))`，
  1=掌面正侧立，0=掌心朝镜头/朝上；`palmSide = nx * SIDE_SIGN`（-1 镜像，反了改 1）。
- 与 `palmUp`（托盘）天然互斥：一个要 |ny| 大，一个要 |ny| 小。

**驱动（`InteractionRouter`，替换原 vortex/push 整段）**：
- `vx` = 手掌屏幕 x 速度（屏宽/秒）→ EMA 0.22 → **软死区** `|vx|-0.15`（不是硬置零，
  否则阈值附近会跳变；软死区能把静止噪声整段减掉，树不会自己漂）。
- 位移积分：`shift += vx*sideW*towardFace*gain*room*dt`；
  `towardFace` 用 palmSide 与 vx 同向判定（同向 1 / 回程 0.45）；`room` 端点软化。
- 输出 `shiftOut` 一阶跟随 7.5Hz；停手 0.28s 后 `exp(-dt*1.4)` 回中。
- `wind` 驱动 storm，`swirl` 改由 handVX 驱动（滑动时粒子带一点绕树转）。
- **位移上限自适应**：`viewWidth`（main resize 时算 `2*tan(fov/2)*16.8*aspect`）×0.20（宽屏）
  或 ×0.13（竖屏 aspect<1.1），clamp 0.7..4.6。否则同一参数电脑上挪不动、手机一滑出画。

**落地**：`ParticleTree.update` 里 `group.position.x = shift`、`rotation.z = -shift*0.010`（约 1.4° 倾斜）；
`SceneEffects` 地面光晕跟 0.7 倍；HUD 提示改 `data-k="slide"`「侧掌扇风」；探针加第四行 `掌/立/滑/风`。
顺手清掉 GestureController 的 `vortexAccum` / `state.vortex` 死字段。

## 修正：扇风不是横移，是绕轴旋转（22:52）

**用户澄清**：不要左右平移，要「树转圈漩涡那种，左右转」——整棵树绕自身中轴旋转。

**改法**（把上一版的位移积分整段换成角度积分）：
- `InteractionRouter`：`shift/shiftOut` → `spin`（累积弧度，±2π 取模）+ `spinVel`（rad/s）。

  **角度不回零**：停下来就停在当前角度，符合"转了一圈"的物理直觉。

  单帧位移大到不可能是真挥动，必须丢掉，否则树会突然反向狂转。这是本版最重要的一处防抖。
- `ParticleTree`：`group.position.x` / `rotation.z` 换成 `group.rotation.y = params.spin`。
- `SceneEffects`：删掉地面光晕的 x 跟随（不再平移）。
- `main`：删掉 viewWidth / viewAspect 自适应（旋转与视宽无关）；探针第 4 行改 `掌/立/转°/速`。
- HUD 文案：「侧掌扇风 · 掌心朝侧 → 树绕轴转」；`swirl` 改由 `spinVel*0.30` 驱动，转动时叠一层粒子涡流。

## 弹幕改英文 + 666 换花体（00:2x）

**需求**：「想我就给我打电话」换成英文；666 也改成和「I love you」一样的艺术字。

**做法**
- `particleSampler.sampleText` 新增 `opts.script` / `opts.spacing`：`script` 走
  `Georgia, "Times New Roman", "Songti SC", serif` 的 **italic 700**，和 LoveMessage 里
  「I love you」同一套字形；顺带支持 `ctx.letterSpacing`（当前两处都留 0）。
- 横向压 0.9 的「汉字补偿」改成只对 CJK 生效（`const squash = cjk ? 0.9 : 1`）——
  花体/数字压了会变成斜瘦条。
- 弹幕文案：`666 / Miss me? / Call me`（三行，中英混排会破坏「一种字体语言」，全改英文）；
  竖屏同一套文案，只收字号与行距。
- 点赞的 666 也走 `script`，字号 1.24(宽)/1.02(竖)。
- HUD 提示「打电话」副标题改成 `Miss me? Call me`。

**这轮踩的坑**
1. **竖屏文字被切边**：`uScale` 收敛系数原来是 0.94，理论上刚好铺满。实测 414×896 时
   z=7 平面可视宽度只有 **3.27** 世界单位，「Miss me?」原始宽 4.81 → 缩到 0.68 后正好
   顶到边，粒子本身的直径 + 泛光再吃掉几个像素，看上去就是两边被削掉。
   改成按布局给边距：宽屏 0.90 / 竖屏 0.84（点赞 0.86 / 0.80）。
2. **点径与亮度是一对**：先是点小(22)+亮(gain 2.1/2.7) → 笔画是散点、断断续续；
   再调大(26)不降亮 → 糊成一团白。最终 `uSize 28` + `gain 1.7/1.9`：
   点给大、亮度压低，靠重叠柔和连成笔画。
3. 星的位置/点径顺手收敛（cfg.size 0.96/0.90、gain 2.1），别跟着 666 一起变胖。
