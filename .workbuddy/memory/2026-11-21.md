## 螺旋浮尘：银白 → 暖金（用户反馈「银白太突出，树主体是绿的」）

**用户的问题**：这层常驻螺旋有必要存在吗？银白配色太突出，树的主体是绿色。

**结论**：保留，但改配色 —— 刺眼的是**色相**，不是亮度。

改动（`src/SpiralRise.js`）：
| 项 | 改前 | 改后 |
|---|---|---|
| 颜色 | 银白 `(0.70,0.82,1.00)`→白 | 暖金 `(1.00,0.77,0.46)`→`(1.00,0.93,0.76)` |
| 颜色乘数 | 1.55 + 0.75·seed | 0.90 + 0.34·seed |
| 亮度 uIntensity | 0.85 | 0.68（竖屏 0.54） |
| 离树皮 | +0.52 | +0.32 |
| 颗数 | 1600（低配 1000） | 1100（低配 720） |
| 高度权重 | 无 | `belly` 0.40~1.0，根部/顶端渐隐 |

**关键实验**：同一页面切三档（0.50 / 0.75 / 1.00）截图对比 → 换暖金后即便 1.00 也不像
银白 0.85 那样抢。原先压到 0.36 时，与关闭螺旋相比只差 1% 平均亮度（实测像素差
平均 +2.84/255、受影响像素 8.15%），等于白开。所以最终定 0.68。

**踩的坑**：
- `belly` 权重收得太窄（smoothstep 0.04~0.30），三条臂在同一高度汇成一圈 →
  看着像给树系了条金项链。放宽到 0.02~0.24 起、0.72~1.0 收，回到「缠绕」。
- 量化像素差不能用两次独立截图：树在自转、雪在飘，噪声淹掉信号（第二次跑出负数）。
  要么冻住渲染循环，要么只靠视觉判断。

**验证**：`.workbuddy/shots/spiral_check.py`（横/竖屏静帧）、`spiral_tune.py`（三档亮度）、
`spiral_diff.py`（可见性开关的像素差）。无 pageerror。

## 点赞特效：五角星 + 666 → 金箔纸屑（`src/Confetti.js`）

**用户反馈**：「我觉得星星有点土」。

**判断**：五角星属于「评分 / 收藏」符号系统（打分、收藏夹、会员星级），
放在雪夜圣诞树前像电商角标；666 是直播间用语。换掉的是**符号**，不是画法。

**新实现**：一整棵树撒下金箔，每片翻转下落、落地淡出，4.8 秒收完。
`LikeBurst.js` 保留作备选（顶部注了怎么切回）。

**四个关键坑（都花了轮次）**：
1. **8 个软圆点拼一片读不出「纸」**：圆点没边缘，叠再多还是点，和雪/彩灯糊成一片。
   → 改成「1 点 = 1 片」，在**片元着色器里用旋转矩形裁形状**：
   `gl_PointCoord` 转到片自己的坐标系，`abs(q) > vHalf` 就 discard。
   边缘只柔 20%~38%，再软又变圆点。
2. **`gl_PointSize` 的换算算错了两个数量级**：公式是
   `gl_PointSize = L * DIAG * uSize / dist`，所以
   `uSize = (viewportH/2) / tan(fov/2) / DIAG`。随手给 62 → 一片只有 1.7px。
   按 900px 视口算应约 990。
3. **`DIAG = hypot(1, ASPECT)` 不能省**：正方点要容下转到 45° 的长边，
   否则斜转瞬间两端被裁。vHalf 要除以 DIAG 补偿。
4. **不要从一点迸发**：试过「树腰一点炸开」，散列 300 片挤在同一位置，
   加法混合下当场烧成白斑。改成按 `radiusAt` 锥面散布 + 错开 0.52s 出场。

**调参**：重力 0.62（不是 9.8，真纸屑有阻力）、片长 0.032~0.062×aSize、
宽长比 0.62、竖屏片径 ×0.62 亮度 0.78→0.66、配色金46/香槟22/银14/橙13/红5。
粒数 2400（低配 1400）。

**验证**：`.workbuddy/shots/confetti_test.py`（横竖屏各 4 帧，按 `L` 触发），无 pageerror。

## 树底地台 + 前景失焦光斑（用户反馈「礼物盒像飘在空中」）

新增 `src/GroundBase.js`、`src/NearBokeh.js`；`SceneEffects` 移除旧的绿色地光贴片
（`groundGlowTexture` 随之删除），地面反照率 `0x0c141d → 0x1c2632`、roughness 0.94 / metalness 0。

**地台四层**：3 盏 PointLight `(0xffd0a2, 12, 11, 2)` 放在 r1.9/y0.62 + 暖光池贴片
（环形，峰值 r2.3~3.0）+ 树冠绿回光环 + 星云 1150 颗上浮粒子 + 69 团地雾。

踩过的坑（重要）：
1. **加色贴片撑不出一块地**。没有法线，低视角下永远是一条横向雾带 —— 必须有真实点光
   走漫反射。three 是物理量：`intensity=1` 完全看不见，要十几；34 直接过曝。
2. **峰值不能在正中心**。树挡掉 r<2.6，中心再亮也看不见，露出来的只是暗尾巴 → 一片暖灰。
3. **画框底边就是 r≈3.9 的地面**（42° 视野、几乎平视）。池半径一拉大（11.2），
   可见渐变就被压成一条横带，像沙丘；收到 8.6 才有衰减。
4. **接触阴影贴着盒底没用**：1440 宽上只有 7~8px；而且盒底被地灯照亮、比地面还亮，
   眼睛只会判「悬空」。改成按「灯在树心」的方向往外拖 1.58:1.34 的软投影，
   `renderOrder=3` > 加色光 1，否则光会吃掉影子。
5. **雾要单团几乎看不见**：69 团 40~120px、单团 alpha≈0.05 才叠出厚度；单团能看清就是球。

**前景光斑**：8 团（竖屏 6），世界 z 5~9.5、尺寸 0.4~1.0 米（屏幕 40~110px），
`gl_PointSize = aSize * uProj / dist`，`uProj = (H*pr/2)/tan(fov/2)`。
三点教训：点精灵中心出裁剪体就整团消失 → 按 NDC 贴边淡出；必须加色混合（普通混合会留方框）；
不能压在树身上（按 `side*(2.6+rand*5.4)` 分左右），否则像镜头脏了。
焦外边缘要留 20% 半径衰减，环一亮就成灰玻璃珠。

**验证**：`.workbuddy/shots/ground_check.py`（全套/关地台/关光斑 + 树底裁切 + 均值对比）、
`ground_tune.py`、`ground_red.py`（染色确认阴影位置）、`bokeh_check.py`、`ground_mobile.py`。
首屏 5.16s 收遮罩、无 pageerror。注意 headless 实际视口比 `--window-size` 小一圈，
必须用 `Emulation.setDeviceMetricsOverride` 钉死 1440×900，否则裁切坐标全错。

## 双手拉弓（取代「抓取张开」）

新增 `src/BowArrow.js`；`GestureController` 加 `BOW_CFG` + `_computeBow()` + `_fireBow()`；
`InteractionRouter` 加 `bowW` 门控；`textures.js` 加 `heartTargetTexture()`；
`gestureConfig`：`burst: false`、`bow: true`；`index.html` 提示条改成「双手拉弓」；
调试键 **B**（`archery.demoShot(t)`，1.1s 拉满后自动放箭）。

**判定**：两手 + 高度差/手宽 < 1.65 + 至少一只手 `clutch|pinch` > 0.52，稳 220ms 出弓；
`pull = smoothstep((间距/手宽 - 1.5)/(4.6 - 1.5))`；放箭 = 合拢速度 < -3.2 手宽/秒
**且** pull 从峰值回落 > 0.26（只看 pull 变小会把「放下手」也当成放箭）。

**必须互相压制的三处**：
1. clap —— 放箭就是两手快速合拢，几何上和拍手同构，不压住每箭都炸一场暴雪；
2. spread 缩放 —— 拉弓姿态就是两手分开，router 会把树推大（`bowW` 让出缩放权重）；
3. heart —— 同是双手，靠「间距 ≥1.5 手宽 vs 比心 <1.3」天然分开，另加 bow 期间直接否掉。

**视觉要点**：
- 整组挂在 camera 下（z = -3.1）= 屏幕坐标，`depthTest:false` + 高 renderOrder；
  相机必须 `scene.add(camera)`，否则子节点不渲染且**不报错**。
- 弓是逐帧重算顶点的折线带（GlowLine），不是贴图 —— 弦要弯、弓梢要后仰。
- 带状面必须横向柔边（1×64 剖面贴图），纯顶点色宽一点就是一根木头。
- 拖影长度按**拉力**算，不按速度（速度单位是局部单位/秒，乘出来是十几个单位，
  屏幕上会拉一条贯穿全场的灰带子）。
- 命中后：红心 0.6s 淡出 + 箭钉在心上 0.26s + 460 颗红金粒子往左上被风带走；
  箭立刻消失会读成「特效掉了」。

**验证**：`bow_check.py`（半拉/拉满/飞行/命中/飘散）、`bow_gesture.py`（假手数据驱动
`_computeBow` 走完整链路：active→pull 0.99→bowW 0.99→scale 1.005→事件触发→flight）、
`bow_portrait.py`（竖屏 414×896）。首屏回归 6.24s / 拒绝 2.42s，无新增报错。

## 拉弓：放宽识别 + 粒子化 + 放箭提示

**用户反馈**：识别不灵敏、不知道怎么发射、弓和心要用粒子效果。

### 1) BOW_CFG 全面放宽（GestureController）
| 参数 | 旧 → 新 | 为什么 |
| --- | --- | --- |
| `levelZero` | 1.65 → 2.30 | 弓斜指左上，人比划自然带斜度，要求水平根本判不出来 |
| `start` / `full` | 1.50/4.60 → 1.12/3.60 | 真人两手在胸前，胳膊展开也就 3 手宽 |
| `gripMin` | 0.52 → 0.30 | 握拳才能过，自然放松的手 clutch≈0.4 → 降到只排除摊平的掌 |
| `hold` | 220 → 150ms | 抬手路过就掉，感觉不跟手 |
| `drop` | 0.26 → 0.15 | 放箭阈值 |
| `peakMin` / `handLossPeak` | 0.42/0.66 → 0.24/0.34 | 半拉也能放 |

**放箭判据砍到只剩一条**：`pull` 从峰值回落 > 0.15（峰值以 1.15/s 衰减，
慢慢放下手 ≈0.5/s 追不上）。**删掉了「两手合拢速度 < -3.2 手宽/秒」**——
手被跟丢重捕时坐标会跳，一帧能造出几百手宽/秒的假速度，凭空放箭。
那个速度现在只用于探针（钳 ±20）。

**新增互斥**：比心期间不判拉弓。放宽 start 之后，比心时「掌间距」也超过 1.12 手宽，
且捏半心 pinch 很高 → 会一边比心一边冒出弓。`_computeBow` 读上一帧 `this.heart` 否掉。

### 2) 放箭提示（index.html + styles.css + main.js）
`#bowTip` 底部中间的进度条，五档文案：`两手指尖分开·一只手半握` → `两手再拉开一点`
→ `继续拉·松手立即放箭` → `已拉满·两手一松就放箭` → `箭已出弦·再拉一次`。
平时隐藏（`opacity`，不用 `[hidden]`，否则过渡失效）。窄屏（≤560px）抬到 bottom:232px，
否则压在手势提示上。

### 3) BowArrow 全粒子化（整份重写）
弓 290 芯 + 210 内光 + 44 外晕 + 90 弦；箭 84 芯 + 26 柔光 + 26 箭头 + 40 尾迹；
心 300 轮廓 + 150 填充 + 70 内部柔光；留 380 颗命中火花。四个 ShaderMaterial，
位置大多在顶点着色器里算（弓臂曲线、弦的 V、心的爆炸）。

踩过的坑：
1. **一层小点 = 一串珠子**（点径 4px / 间距 5px）。必须三层尺寸叠出伪 bloom。
2. **外晕散太开 + 绿分量不足 = 褐色脏雾**。`aOff ±0.8`、`g = 0.70r`。
3. **箭杆点径必须大于点间距**，且颜色要从尾到头渐亮，否则是一条白棍。
4. **尾迹只在飞行时亮**（`uTail`），搭在弦上拖长尾巴是穿帮。
5. **心的填充不能用「轮廓点×半径」**：x≈0 的点全叠在竖轴上 → 一根穿心的骨刺。
   改包围盒拒绝采样 + 射线法判内外。轮廓要**按弧长**采样（均匀取 t 会在尖端堆一坨）。
6. **竖屏弓被切掉一半**：`bx` 必须 `min(0.62*rx, rx-1.02)`；unit 0.215→0.180。
7. **点精灵尺寸要用绘制缓冲高度**（vh*pr/2/tan），否则 2 倍屏小一半。

顺带修掉树底那只过曝成纯白的礼物盒（`0xd8d0c0` → `0xb2a691`）。

**验证**：`bow_check.py`（半拉/拉满/飞行/命中/飘散）、`bow_gesture.py`（假手驱动：
抬手不误触 → 七成 → 拉满 → 松手放箭 1 次 → 慢慢放下手不误射 → 丢手 1 次）、
`bow_portrait.py`、`boot_check.py`（拒权 2.40s 收遮罩）、`probe_check.py`。无新增报错。
